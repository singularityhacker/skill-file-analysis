How a Skill Gets Invoked
1

You type a command

/tdd, /ship, /review -- or describe a task in plain language

2

Router matches it

Root skill or plugin system maps your input to the right SKILL.md

3

Skill loads on demand

Only that skill's SKILL.md enters context. Not the whole pack. Token-budgeted.

4

Agent follows it

The SKILL.md contains structured instructions the agent executes as a workflow

Two Types of Invocation

User-Invoked

You type the command. The agent can never fire this on its own. Used for high-stakes workflows where human intent matters.
# You type:
/ship
/grill-with-docs
/setup-pstack

Model-Invoked

The agent decides to fire this when the task matches trigger phrases in the skill's metadata. Happens autonomously during work.
# Agent sees you debugging, auto-fires:
/diagnosing-bugs

# Agent hits a design question, auto-fires:
/prototype
How Users Find the Right Command

Gstack

Root Router
The root SKILL.md pattern-matches natural language. Describe what you want; it routes you to the right skill. No memorization needed.
Also: /learn
Shows what gstack has learned and what's available.

Pstack

/poteto-help
"Stuck, or unsure which skill fits? Ask." Recommends the right skill or playbook and gives you the prompt to send.
Also: Cursor's / menu
Browse all registered skills in the IDE's slash-command picker.

Matt's Skills

/ask-matt
"You don't remember every skill, so ask." Maps your situation to the right skill or sequence. Recommends and stops; never starts work itself.
